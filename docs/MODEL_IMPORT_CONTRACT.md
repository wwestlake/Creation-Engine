# Djehuti Model Import Contract

## Purpose

Every imported model reaches the renderer through one coordinate contract.
Characters, scene instances, cameras, physics, and gameplay do not repair an
asset's axis or size. The model importer establishes the contract once, the
asset catalog retains it, and the renderer applies it after skinning.

## Canonical Space

- One Djehuti length unit is one metre.
- Djehuti world space is right handed: `+X` right, `+Y` up, `-Z` forward.
- Mesh vertex positions, skeleton bind matrices, inverse-bind matrices, and
  animation channels stay in the same source model space until skinning is
  complete.
- Scene `Transform` and parent relationships express authored placement only.
  They never carry a source-tool conversion.

## Import Boundary

`Source/Render/Import/GltfLoader.cpp` is the only code permitted to interpret
glTF source coordinates. It produces:

1. Source node hierarchy with source scale excluded from Djehuti's unit
   declaration.
2. Source inverse-bind matrices copied exactly from the glTF accessor.
3. A `LoadedModel::modelSpaceBasis` when an explicitly recognized legacy
   wrapper needs a source-space-to-Djehuti-space conversion.

`AssetCatalog` persists that basis with the model hierarchy. An instance gets
an `ImportedModelSpace` component while it resolves its mesh asset reference.
`ViewportComponent` multiplies that basis after the entity's world transform
and after skinning. No player, Puppet, camera, physics, or animation path is
allowed to add an axis or scale correction.

## Legacy Blender Wrapper

The current Editor Main Female export is generated by Blender and contains a
single un-authored wrapper with a `+90` degree X rotation and uniform `.1`
scale. Its mesh vertices are already approximately 1.99 source units tall.
That wrapper is conversion baggage from the MakeHuman/FBX/Blender path, not
the character's intended scale or pose.

The loader recognizes only this narrow shape:

- glTF generator identifies Blender I/O;
- root node has no parent;
- rotation is `+90` degrees around X;
- scale is uniformly `.1`.

For that exact legacy form, the wrapper is neutralized and a `-90` degree X
post-skinning basis converts the retained Z-up metre geometry to Djehuti Y-up.
Other Blender roots and all other glTF transforms remain authored data. This
is a compatibility adapter, not a heuristic applied to every model.

## Export Requirements

New Djehuti Bridge exports must declare their coordinate and unit contract in
the export metadata and bake source-tool conversion wrappers before publish.
The importer will validate, rather than guess, those declarations once the
Bridge metadata field is available. Until then, an unsupported non-canonical
model should report its measured bounds, root transforms, and source generator
as an actionable import error rather than silently receive a rotation.

## Validation

For a skinned humanoid import, validation must report:

- raw mesh bounds and measured height;
- source generator and detected root conversion state;
- canonical model-space basis;
- skeleton joint count and inverse-bind count;
- bind-pose identity check: `jointWorld * inverseBind` must leave each
  weighted mesh in its bind pose;
- feet-on-ground bounds after the canonical basis is applied.

The acceptance test for Editor Main Female is a roughly 2 m upright character
whose bind pose, animation palette, and visible clothing agree without a
per-character transform adjustment.
